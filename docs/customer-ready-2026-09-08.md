# Connact.ai 本次交付与验证（2026-09-08）

本地入口：<http://127.0.0.1:3100>。目前运行真实 API 配置和生产前端，可在本机实际搜索、补全人员资料、解析简历和写邮件。邀请注册、账号隔离及容器已验证，可用于准备小规模客户试用；本次没有部署公网服务器，也没有接通 Gmail 发送。

## 1. 人员信息：分开获取、分开保存

路径为 **SerpAPI Google 搜索 → LinkedIn 身份定位 → Apify 公开档案补全**。工作邮箱另行选择 Apollo 或 Apify，获取邮箱不是搜索成功的前提。

- 搜索结果保留标准化 LinkedIn URL、来源和搜索历史；保存联系人后可独立补全基础信息、简介、工作履历及教育经历。
- 搜索、档案和邮箱任务落库，有进度、缓存、错误和重试。切换页面后可重新查看。已记录上游 run ID 的 Apify 任务可继续查询，避免重新收费。
- 手工修改联系人会使旧身份缓存失效；后台结果不能覆盖修改后的身份。空邮箱结果不清空已有邮箱。
- 缺失字段明确显示；电话未请求。提供商返回的邮箱有效性保留为来源声明，应用不声称已自行验证投递。

真实验证：一条金融搜索取得 10 个 LinkedIn 结果；一个公开档案取得 **5 段工作履历、3 段教育经历**。Apify 邮箱试验一人无结果、另一位取得商业邮箱，共消耗 **$0.024**。Apollo 当前 key 的 `people/match` 仍返回 **403 / API_INACCESSIBLE**，因此 Apify 邮箱查询作为明确可选路径，而不是暗中降级或伪造成功。覆盖率不能由这几个样本推断。

详情：[提供商验证](people-provider-verification.md)。

## 2. 写作：参考新建 Sequence 后的邮件步骤

重点检查了已登录 Apollo 的 `Yinba's Outbound AI Sequence 1`，包括 Assisted / Prompt / Template、Context center、个性化证据、预览和插入。观察的是可见行为，没有复制私有代码或声称掌握其内部 Prompt。

Connact.ai 已支持引导写作、自定义 Prompt、手写模板三种方式。每份草稿独立保存目的、CTA、语气、语言、长度、模型、补充要求，以及可选的联系人和职业画像。用户可以先写草稿、以后再选人，也可以先保存画像或搜索结果后离开。

- 已接通百炼 **Qwen Plus / Turbo / Max**，三个模型均真实返回 HTTP 200。
- 生成时冻结草稿版本、画像版本、联系人和所选证据；结果先作为建议保存，点击“插入建议”才修改正文。
- 生成期间可编辑或离开；重新进入可恢复任务和历史。上下文发生变化时，过期建议不能覆盖新内容。
- 自动保存处理延迟请求、失败恢复和跨草稿切换；预览解析变量，缺少必要变量时提示补全。
- 可复制邮件，或在收件地址与变量完整后导出未发送 `.eml` 文件。

真实 UI 验证完成了一封未绑定联系人、未绑定画像的英文草稿：后台生成 → 审核 → 插入 → 刷新，主题、正文和写作要求均保留。该测试草稿留在本地邮件工作室，签名仍需用户填写。没有发送邮件。

详情：[Apollo 流程与实现映射](apollo-sequence-writing.md)。

## 3. 同时补全的使用问题

- 简历解析改为持久化后台任务，记录解析结果和文件；可离开页面、查看历史、失败重试。同一文件的相同解析任务复用结果。
- 解析结果先供确认，选择“使用解析字段”才更新表单；不会悄悄覆盖手工输入。
- 邀请模式提供单次、限时、绑定邮箱的邀请码；密码哈希、可撤销会话、HttpOnly Cookie、独立客户工作区和跨账号访问限制已实现。
- 公网配置必须启用邀请模式和 HTTPS；密钥只在服务端本地配置，不进入前端构建、Git 或交付说明。
- 容器补全品牌静态资源和非 root 用户目录权限，构建上下文排除密钥与本地测试产物。

## 5. 客户试用边界

本次完成的是可运行的功能和邀请试用基础设施。公网域名、服务器和 TLS 仍需实际部署配置；Gmail OAuth、应用内发送、自动多步骤跟进尚未实现。目前通过复制或 `.eml` 交给客户邮箱发送。

后台 worker 目前要求单 API 进程。大规模开放前还需要客户额度、分布式任务、监控、备份恢复演练及账号恢复操作流程；当前没有公开自助注册、计费或完整管理员界面。

部署和邀请客户的具体命令见 [客户试用指南](customer-trial.md)。
