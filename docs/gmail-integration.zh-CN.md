# Gmail 真实接入与验收

平台 Google 登录与 Gmail 邮箱授权分别进行。可以连接多个邮箱，发件邮箱不必与平台登录邮箱相同。程序不会把模拟成功当作真实发送。

## 配置

1. 在 Google Cloud 对应项目启用 **Gmail API**，在 OAuth 的 Audience 中加入测试邮箱。
2. 在 Web OAuth 客户端保留原登录回调，另加 Gmail 回调：

   ```text
   http://127.0.0.1:3100/api/mailboxes/callback
   https://connact-ai.onrender.com/api/mailboxes/callback
   ```

   本地和部署环境分别配置对应地址。不要把邮箱回调替换成登录回调。
3. 后端可复用 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`；如使用独立 Gmail 客户端，填写 `GMAIL_CLIENT_ID` / `GMAIL_CLIENT_SECRET`。密钥不应发到聊天、前端或仓库。
4. 后端设置持久的 `GMAIL_TOKEN_ENCRYPTION_KEYS`。该密钥必须与数据库分开保管；丢失后需要重新授权邮箱。当前本地环境已补充加密配置，部署环境需要独立设置。
5. 运行数据库迁移并重启。项目根目录执行 `./scripts/dev.sh` 会处理迁移和本地启动。云端 Docker 启动也会先执行迁移。详情和密钥生成命令见 [English guide](gmail-integration.md)。
6. 打开 **Mailboxes / 邮箱**，选择“仅发送”或“发送并同步”，阅读披露并完成 Google 授权。

## 测试账号被拒绝：`403 access_denied`

如果 Google 提示“应用正在测试中，仅获开发者批准的测试人员可以访问”：

1. 将授权请求里的 `client_id` 与 **Google Auth Platform → Clients / 客户端** 核对，选择包含这个客户端的项目。独立的 `GMAIL_CLIENT_ID` 可能与平台登录使用不同项目，不能只看应用名称。
2. 在该项目进入 **Audience / 受众 → Test users / 测试用户 → Add users / 添加用户**，加入本次实际选择授权 Gmail 的 Google 邮箱并保存。发布状态保持 **Testing / 测试中**。
3. 返回平台 **Mailboxes / 邮箱** 重新发起连接，并选择刚加入的同一个账号；不要复用原来的错误页地址。

Google 可能在返回平台之前就阻止授权；即使回到平台，目前也只显示通用的“授权未完成”，应结合 Google 错误页识别这个测试用户限制。

基本 Google 登录只请求身份权限，可以在未加入测试名单时正常使用；Gmail 授权请求额外权限，测试阶段需要获得测试访问资格。添加测试用户不代表完成生产环境的权限审核。参见 [Google 受众说明](https://support.google.com/cloud/answer/15549945?hl=zh-Hans)。

## 隐私和发送规则

- 收件箱只展示当前工作区已保存联系人邮箱精确匹配的邮件。未保存的搜索候选人不纳入同步；不会按公司域名批量放开。
- 先检查邮件头，再取符合条件的正文。已知会话里的陌生发件人不会因此获得展示权限。每次读取时重新验证联系人状态与邮箱；同步过程中获取和保存正文前也会重新查询，处理联系人被修改或取消保存的情况。
- 支持精确邮箱、邮箱域名、意向、待我回复筛选及分页。域名筛选只缩小已保存联系人范围；待我回复表示会话中最新可见邮件为入站且未被识别为自动邮件。
- Google 的权限本身不能限制到几个联系人。平台负责执行这个过滤，不能宣称 OAuth 技术上只能读取这几个人的邮件。
- 首次同步最近 30 天，随后约每两分钟增量同步。只读/归档标记同步到 Gmail；备注、意向和提醒保存在平台。
- 发信前确认发件邮箱、联系人、内容版本和时间。Gmail 接受请求才记为已发送，这不等于已经投递或被阅读。
- 回复沿用原会话。收到联系人邮件会暂停相关待发送任务；同步失败或授权失效会阻止依赖最新收件状态的任务继续发送。
- 手动跟进到期只显示提醒，必须由用户主动写信并发送。发送结果不明时不自动重试。
- 断开邮箱会清除本地令牌并停止任务，默认删除已导入邮件；不会删除 Gmail 原件。Google 授权可在 [账号连接管理](https://myaccount.google.com/connections) 撤销。

## 真实验收

指定一个测试收件邮箱，在平台保存为联系人后发测试信；确认对方收到并回信，再检查平台收件箱。加入一封无关邮件以验证它不会出现；验证另一账号、取消保存或修改邮箱后不可读取原邮件；验证新回复暂停定时任务、提醒到期不自动发信。

自动化测试通过只能证明代码在隔离测试中的行为。真实 Google 授权、发送、收取回复和线上部署必须分别验收。Google 登录可用不代表 Gmail 的受限权限审核已经完成。
